JOB OFFER LIFECYCLE MANAGEMENT (7.1.29) === CONTEXTE === Before connecting a real AI provider (Gemini) to generate opportunity explanations, the system must avoid spending tokens on stale or already-filled job offers. The repository audit performed for this phase found that JobOffer.status, JobOffer.archived_at, UserSettings.discovery_age_window and UserSettings.discovery_show_archived all already exist in the data model, but none of them are ever written or read by any actual business logic. The offer lifecycle feature was designed at the schema level but never implemented end-to-end. The audit also found that JobOfferSource.last_seen_at already exists and is exactly the field needed to detect offer removal from a source, but JobOfferRepository.attach_source() currently returns the existing link unchanged when it already exists, without ever refreshing last_seen_at. This single gap is the reason the removal-detection mechanism has never worked, despite the schema being ready for it. === DECISIONS === --- Detection strategy: comparison against the previous sync batch (Option B) --- At every DiscoveryService.import_from_connector() run, before processing the newly fetched offers, the system records which JobOfferSource rows existed for that JobSource prior to this run. After processing the batch, any pre-existing JobOfferSource row for that source whose last_seen_at was NOT refreshed during this run is considered no longer present in the source's current listing (i.e. likely filled or removed by the employer). This requires attach_source() to always update last_seen_at (and updated_at) to the current timestamp when the link already exists, not just return it unchanged. --- Retention rule --- - A JobOffer becomes eligible for permanent deletion when: - its most recent JobOfferSource.last_seen_at (across all sources attached to it) is older than discovery_age_window (see below), OR - it was detected as removed from its source during the most recent sync of that source (see detection strategy above). - A JobOffer is NEVER deleted if at least one Application references it via Application.job_offer_id. This is already guaranteed at the database level: the foreign key has no ondelete clause, defaulting to RESTRICT in PostgreSQL. The cleanup service will explicitly filter out offers with at least one related Application before attempting deletion, to avoid relying solely on catching a database integrity error. - Deletion is permanent (hard delete), per Vincent's explicit decision. This supersedes the "offers are archived, never deleted" rule previously documented in DEC-041. See DEC-086 below. --- Age window configuration --- - Default: 30 days, already stored in UserSettings.discovery_age_window (existing field, currently unused by any business logic). - The existing field will finally be read by the new cleanup service. No new column is introduced; this closes the gap between the Settings UI (already functional since 7.1.25) and the actual pipeline. --- Out of scope for this phase --- - LinkedIn connector remains unconnected (no real scraping implemented, per Vincent's confirmation: LinkedIn's scraping policy raised unresolved concerns). This is tracked separately and is not part of this lifecycle cleanup work. - Per-source configurable age windows (e.g. a different retention for LinkedIn vs France Travail) are not introduced now; the single existing discovery_age_window setting applies uniformly. A future refinement could introduce per-source overrides if needed. === BACKEND CHANGES === --- backend/app/jobs/job_offer_repository.py --- attach_source() is modified so that when existing_link is found, last_seen_at and updated_at are refreshed to the current timestamp before returning it, instead of returning it unchanged. --- backend/app/jobs/job_offer_cleanup_service.py (new file) --- A new service responsible for identifying and deleting stale offers: def find_stale_job_offer_ids(db, age_window_days: int) -> list""" Returns the ids of JobOffer rows whose most recent JobOfferSource.last_seen_at (across all attached sources) is older than age_window_days, AND that have no related Application.
